# 模型外部运行系统成为研究新焦点

**大模型研究热点· 2026 年第 34 周**

**观察窗口：2026 年 8 月 14 日至 8 月 20 日**  
**论文筛选窗口：2026 年 5 月 20 日至 8 月 20 日**

> 一句话判断：本周值得关注的变化不是“模型又大了多少”，而是研究开始深入模型外部的运行系统，包括 skill 选择、记忆路由、harness 自进化，以及强化学习对策略空间和未来可训练性的隐性影响。

## 一、本周研究热点

### 1. Skill 研究从“有没有用”转向“为什么失效”

本周最直接的信号是 [Demystifying Agent Skills](https://arxiv.org/abs/2608.14036)。论文整理了 8,135 条受控实验记录，发现 skill 相比 workflow memory 平均提升 6.06 个点，但其中约 65.7% 的收益来自“程序性锚定”，只有 4.5% 可归因于显式知识注入。换句话说，skill 的主要价值可能不是教会模型新知识，而是约束它以更稳定的步骤结构行动。

更值得注意的是 skill 池扩张问题：候选 skill 从 5 个增加到 100 个时，实际使用精度从 29.6% 降到 3.3%。而且，“检索到了正确 skill”既不是任务成功的充分条件，也不是必要条件。接下来的关键问题会是：如何判断 skill 是否适用于当前状态，以及如何在执行中修改、组合或放弃 skill，而不仅是把它检索出来。

**趋势判断：** Skill retrieval 很可能会演化成 skill routing、adaptation 和 failure attribution 三个子问题。

### 2. Memory 正在变成“存储介质路由”问题

[Harness the Memory](https://arxiv.org/abs/2608.15008) 对 11 种方法、7 类记忆载体、3 个模型和 4 类 benchmark 做了统一比较。结果没有发现普遍最优的 memory substrate：宽泛检索有利于长上下文问答，却可能在连续决策中分散模型对当前关键状态的注意力；图结构在对话问答中表现较好，但在 agent 任务上可能被更简单的精炼式记忆支配。

这意味着“给 agent 加一个向量数据库”并不是完整的研究问题。真正值得做的是根据任务、查询和当前轨迹，决定使用 episodic memory、结构图、规则摘要还是压缩后的 refinement memory，同时决定应该写入什么、何时忘记、检索多少。

**趋势判断：** 下一步可能不是更强的统一 memory，而是可学习的 memory router，以及训练时优化的 write policy。

### 3. Harness 从人工脚手架走向可训练对象

近期几项工作同时指向这一方向，包括 [EvoHarness-RL](https://arxiv.org/abs/2608.05446)、[The Horizon Gap](https://arxiv.org/abs/2608.06663) 和 [Long-Horizon Agent Trajectory Attribution](https://arxiv.org/abs/2608.06909)。

这里的 harness 不只是提示词，而是模型周围的运行系统：工具接口、状态管理、上下文组装、错误恢复、验证器和轨迹压缩。过去通常固定 harness、训练 policy；现在开始出现让 harness 根据失败轨迹自我修改，或者把 harness 配置本身当作策略搜索空间的工作。

**尚未解决：** Harness 的改进很容易对特定 benchmark 过拟合。需要区分它是在学习可迁移的工作流，还是在积累某个评测环境的隐藏答案和捷径。

### 4. RLVR 的核心风险从“奖励欺骗”扩展到“支持集坍缩”

本周两篇工作提供了互补信号：[Verifier-Induced Support Reshaping](https://arxiv.org/abs/2608.00220) 研究某个任务上的 RLVR 如何降低模型在后续任务中采样到成功轨迹的概率；[BODHI](https://arxiv.org/abs/2608.02867) 则发现 RLVR 会明显减少语义层面的推理分支。

这比普通遗忘更隐蔽。模型在当前任务的 pass@1 可能提高，其他任务的贪心准确率甚至也没有下降，但成功轨迹已经变得极难采样，导致后续 RL 没有正样本可以强化。以后评价 RLVR，可能必须同时报告 pass@1、best@k、语义分支熵和后续任务的可训练性。

**趋势判断：** “保留多少知识”将逐渐让位于“保留多少可探索、可强化的策略路径”。

### 5. Critic 的表示与校准重新成为有效杠杆

[Start Classifying](https://arxiv.org/abs/2608.02181) 表明，将传统的标量 MSE critic 换成分类分布式 critic，在不改变 PPO actor 更新的情况下，也可能显著改善训练。作者认为关键不只是 value prediction 更准确，而是减少 critic 对失败轨迹的极端 advantage 估计。

这重新打开了一个一度被简化的问题：critic 应该输出一个标量、一个分布，还是带不确定性的结构化判断？如果 critic 的校准能降低错误的大幅更新，它还可能缓解探索坍缩和稀有成功轨迹消失。

### 6. Reward 从固定规则走向“随模型能力一起进化”

[AudioRubrics](https://arxiv.org/abs/2608.02831) 尝试为每条音频样本生成独立 rubric，并在训练中删除已经失去区分度的标准，再根据当前 policy 的错误生成更难的新标准。

这让 RL 可以进入缺少唯一标准答案的任务，但也带来新的依赖：当 rubric generator 或 judge 不够强时，训练效果可能比普通 GRPO 更差。因此，“自进化奖励”值得关注，但必须同步研究 judge 校准、偏差累积和奖励标准漂移。

## 二、论文导读：5 篇可找灵感的新工作

### 1. Verifier-Induced Support Reshaping in On-Policy Optimization

**中文译名：** 验证器诱导的在线策略优化支持集重塑

[论文](https://arxiv.org/abs/2608.00220) · [代码](https://github.com/sylvain-wei/verifier-induced-support-reshaping) · 2026-07-31

**作者：** Shaohang Wei, Zikun Su, Feifan Song, Wen Luo, Wei Li, Guangyue Peng, Houfeng Wang

**一句话灵感：** 评价一次 RL 训练时，不只检查旧能力是否还在，还要检查模型是否仍能在有限采样中找到下一项任务的成功路线。

**通俗理解：** 这像训练司机只走当前最快的主路：眼下到得更快，但通往其他目的地的小路入口逐渐被忘掉。主路对应当前 RLVR 任务，小路对应其他任务的成功轨迹，有限 rollout budget 就是司机只有有限次数寻找入口；论文关心的不是地图知识是否消失，而是入口是否还找得到。

**重要性：** 这项工作区分了“还能答对”和“还能继续学会”。模型在另一个任务上的单次准确率可能没下降，成功路径却已稀少到训练时采不到，后续 RL 因而缺少正奖励；这说明持续训练需要测量未来可训练性，而不只是遗忘率。

**动机：** 现有连续训练常用 pass@1 判断旧能力有没有保留，但它只观察最可能的一条输出。作者关注一个更早出现的失败：策略分布虽然还藏着正确路线，有限次采样却几乎碰不到它，因此正确路线无法再被强化。

**创新：** 作者定义了 effective rewardable support，即在给定 rollout 数量下实际能被采样并获得奖励的轨迹集合，并用数学与指令遵循任务做双向训练。分析进一步把变化定位到回答开头几个 token，表明 RLVR 可能先改变“选择哪条解题路线”，再改变后续推理内容。

**怎么验证：** 作者在 Qwen3-8B-Base、Qwen2.5-Math-7B 上训练，并用数学题和指令遵循任务交叉测试。数学 RLVR 让 Qwen3-8B 第一次作答的成功率提高 6.5 个百分点，但连续尝试 32 次时“至少找到一次正确路线”的比例反而下降 9.8 个百分点；这正说明常用路线变强了，备用路线却变少了。局限是任务类型较少，部分结果也只使用固定随机种子。

**可以怎么往前做：** 可以在训练中定期估计另一任务的成功轨迹密度，并将其作为约束；也可以只对回答开头的路由 token 加探索正则，与全序列 KL 比较，看哪种方法更能保住 best@k 和第二阶段学习速度。

### 2. BODHI: Do LLMs Branch Out and Discover Heterogeneous Inferences?

**中文译名：** BODHI：大语言模型是否会拓展并发现不同的推理路径？

[论文](https://arxiv.org/abs/2608.02867) · 2026-08-03

**作者：** Soumadeep Saha, Krish Sharma, Akshay Chaturvedi, Nicholas Asher

**一句话灵感：** 不要用“说法不同”冒充“思路不同”，应直接度量模型是否探索了不同的语义推理分支。

**通俗理解：** 这像问五个人怎么去车站：他们可能分别说“直走”“一直往前”“沿路前行”，听起来有三种答案，其实走的是同一条路。句子差异对应表面文本多样性，真正选择不同街道才对应语义分支；BODHI 就是在画出这些真实路线的分叉图。

**重要性：** 过去常根据模型“下一个词有多随机”或答案措辞有多不同来判断探索程度，但这些指标会把同一思路的改写误算成新路线。BODHI 显示 RLVR 可能在提高单次正确率的同时剪掉有效备选解法，因此需要直接观察推理分叉，而不只是文字变化。

**动机：** 如果只看文本形式，模型生成许多不同句子时会显得很有创造力；但这些句子可能共享同一个错误或同一个中间判断。作者希望识别模型在关键决策点究竟考虑了多少个语义上不同的下一步。

**创新：** 方法先把“意思相同、说法不同”的推理步骤合并成同一节点，再把前后步骤连成一棵推理树。它随后统计模型在每个路口把概率分给多少条不同路线；概率越集中，说明模型越倾向只走一条路。这样就能把文字改写与真正的解题分支分开。

**怎么验证：** 作者让 3B 至 32B 模型解迷宫和 235 道 AIME 数学题，收集约 2 万条完整推理路线，并比较普通微调、蒸馏和 RLVR。作者报告 RLVR 模型更少走无效步骤，却也明显减少语义上不同的备选路线；多数统计检验达到 `p < 0.0001`。局限是“两个步骤是否同一种思路”仍由另一个大模型判断，而且只测了迷宫和数学。

**可以怎么往前做：** 可以把 semantic branch entropy 作为 RLVR 的轻量奖励，观察能否保住 best@k 而不明显损伤 pass@1；也可以把树节点换成 agent 的计划与工具调用，区分“参数不同”与“方案真正不同”。

### 3. Start Classifying: Categorical Critics for LLM Reinforcement Learning

**中文译名：** 从分类开始：用于大语言模型强化学习的类别型价值评估器

[论文](https://arxiv.org/abs/2608.02181) · [代码](https://github.com/ZhijianZhou/HL-guass-ppo) · 2026-08-03

**作者：** Zhijian Zhou, Long Li, Xuan Zhang, Zongkai Liu, Yulei Qin, Ke Li, Xing Sun, Xiaoyu Tan, Chao Qu, Yuan Qi

**一句话灵感：** 与其让负责估分的 critic 硬猜一个精确分数，不如让它先判断结果更可能落在哪个分数区间。

**通俗理解：** 这像天气预报不只说“明天 23.7 度”，而是给出 20 至 25 度最可能、其他温度也有多少概率。传统 critic 的单一温度对应标量 value，分类 critic 的多个温度档对应回报分布；后者即使猜偏，也较少因一个离谱数字让 actor 做出过猛调整。

**重要性：** PPO 里有两个模型角色：actor 负责生成答案，critic 负责预估这次答案大概能得多少奖励。这篇论文没有改负责答题的 actor，只改了 critic 的估分方式，结果仍然提升明显；这说明训练不稳定有时不是“答题模型不会学”，而是“估分员给错了更新力度”。

**动机：** 传统 critic 必须直接猜一个精确分数，猜错多少就会影响 actor 这次该改多大。遇到奖励稀疏、结果只有成功或失败的任务时，少量离谱估分可能让模型一次调整过头，即使 critic 的平均误差看起来并不严重。

**创新：** 新方法不再让 critic 直接输出一个数字，而是把可能的奖励划成多个区间，并输出每个区间的概率，最后再算出平均估分交给 PPO。由于相邻区间也会分到少量概率，某个样本不容易把估分拉到极端；actor 的训练规则则完全不变。

**怎么验证：** 作者在 Qwen 4B 至 7B 模型上测试数学、工具辅助数学和搜索任务。数学汇总分数从普通 PPO 的 15.88 升至 18.74；每题尝试 256 次时“至少成功一次”的比例从 38.48 升至 48.06，critic 的概率校准误差也更低。局限是模型家族和规模较单一，而且尚未证明“估分更准”就是性能提升的唯一原因。

**可以怎么往前做：** 可以控制 critic 的预测误差不变、只改变校准程度，检验校准是否真的减少语义分支坍缩；也可以让 critic 同时输出回报和不确定性，只对高置信样本执行大幅更新。

### 4. Reinforcement Learning with Evolving Rubrics as Rewards for Audio Reasoning

**中文译名：** 面向音频推理的动态评分标准奖励强化学习

[论文](https://arxiv.org/abs/2608.02831) · [项目页](https://audiorubrics.github.io) · 2026-08-03

**作者：** Fangxu Yu, Tao Feng, Dehai Min, Zinan Lin, Weijia Xu, Michael Xu, Philip S. Yu, Ge Liu, Tianyi Zhou

**一句话灵感：** 当固定评分标准已经不能区分模型好坏时，让评分表根据模型当前错误同步升级。

**通俗理解：** 这像教练训练运动员：初学时检查动作是否完成，熟练后便删掉这项人人满分的标准，改看节奏和细节。运动员是被训练模型，评分表是 rubric，教练根据当前表现改题就是 evolving rubric；难点在于教练自身必须足够可靠。

**重要性：** 许多开放式和多模态任务没有唯一标准答案，无法直接使用可执行 verifier。动态 rubric 提供了一条把 RL 扩展到这些任务的路径，并提醒我们奖励函数也会随着 policy 进步而“过期”。

**动机：** 固定 rubric 太简单时，所有 rollout 很快都拿高分，训练失去区分信号；一开始就设得太难，又会让所有输出同样低分。作者希望评分难度始终贴近模型当前能力，让 reward 在整个训练过程中保持可辨别性。

**创新：** 系统从每条原始音频生成专属 rubric，在 GRPO 训练中删除已经无法区分 rollout 的标准，再根据当前错误生成更难的新标准。最终奖励组合了任务结果、动态 rubric 和过度思考惩罚，使“评分什么”与模型能力一起变化。

**怎么验证：** 作者用 40,176 条音频问答数据训练 Qwen2.5-Omni-7B，并让 Gemini-3.1-Pro 负责生成和检查评分标准。相对固定奖励的 GRPO，完整方法在三个音频评测上分别从 75.20、62.20、63.14 提升到 78.00、65.80、65.86。可是换成能力较弱的评审模型后，效果可能还不如普通 GRPO，说明方法很依赖“出评分表的老师”是否可靠。

**可以怎么往前做：** 可以用多个较弱 judge 的分歧来触发 rubric 更新，测试能否替代单一强 judge；还可以测量新 rubric 是否真的提升任务难度，而不是逐渐偏向生成器熟悉的表达方式。

### 5. Don't Peek at the Answer: Outcome-Masked Group Relative Policy Optimization for Label-Free RLVR

**中文译名：** 别偷看答案：面向无标签 RLVR 的结果屏蔽式组相对策略优化

[论文](https://arxiv.org/abs/2608.03119) · 2026-08-04

**作者：** Yongshi Ye, Liang Zhang, Yidong Chen, Xiaodong Shi, Biao Fu

**一句话灵感：** 仍然用最终答案判断回答好不好，但不直接训练模型模仿最终答案，只训练它前面的推理过程。

**通俗理解：** 假设老师没有标准答案，只看到十名学生中七人选了 A，于是暂时认为 A 更可能正确。普通方法会同时表扬解题过程和最后写下的 A，学生很快便学会跟着多数人填 A。OM-GRPO 仍用多数答案评分，但把答题卡上的 A 遮住，只根据这个分数训练前面的草稿步骤。

**重要性：** 无标签训练不需要人工准备标准答案，但多数人选择的答案不一定正确。如果模型因为“A 出现得多”就不断强化 A，错误会自我复制。这篇论文说明：评分依据可以来自最终答案，但训练时不一定要直接强化答案本身。

**动机：** 传统多数投票方法先让模型生成多份答案，再把出现最多的答案当作临时标准答案。问题是，模型可能只学会输出这个高频答案，而没有学会更可靠的推理方法。训练分数看似提高了，真实解题能力却可能没有提高。

**创新：** OM-GRPO 给整条回答计算奖励，但在更新模型时跳过最后的答案部分，只调整答案之前的推理文字。它还会从已经生成的解答中选出两份进行比较，判断哪份更可信，以修正简单多数投票产生的分数，不需要额外生成一批答案。

**怎么验证：** 作者在 Qwen3-1.7B 等不超过 7B 的模型上训练，并在数学、代码和指令遵循等九项任务测试。九项平均分中，直接使用真实答案训练得到 35.55，多数投票得到 32.64，OM-GRPO 得到 35.19，接近有真实答案的训练。局限是多数意见本身仍可能出错，而且尚未验证更大的模型。

**可以怎么往前做：** 可以把同样的方法用于工具型 agent：根据任务最终是否完成来打分，但不直接强化“提交成功”这类最后动作，只训练之前的规划、搜索和工具调用。然后观察 agent 是否减少钻评分规则空子的行为，并在新任务上获得更好的迁移能力。

## 三、本周最值得动手的三个研究问题

### 1. 动态 memory router 是否能稳定胜过固定记忆架构？

**可证伪假设：** 在相同 token、延迟和存储预算下，根据任务状态选择 episodic、graph 或 refinement memory，会同时提升长上下文 QA 与连续决策表现。

**最小实验：** 选两类 QA 和两类 agent benchmark，用一个小型 gating model 在三种 memory substrate 间路由；与单一 substrate、全量混合检索比较，并严格匹配检索 token 数。

### 2. 语义分支熵约束能否防止 RLVR 破坏未来可训练性？

**可证伪假设：** 对推理树关键节点加入轻量 semantic entropy bonus，可以保持 best@32 和后续任务 rewardable support，同时让当前任务 pass@1 的损失不超过 1 个百分点。

**最小实验：** 使用 1.5B 至 3B 数学模型，在两个顺序训练任务上比较普通 GRPO、token entropy bonus 和 semantic branch entropy bonus；记录 pass@1、best@32、分支熵及第二阶段达到目标分数所需 rollout 数。

### 3. “奖励位置与梯度位置解耦”能否迁移到工具型 agent？

**可证伪假设：** 屏蔽终局答案和 verifier 相关 token 的梯度，只更新计划与工具交互 token，会降低 reward hacking，并改善未见工具或新环境上的迁移。

**最小实验：** 在一个搜索 agent 和一个代码 agent 环境中构造可利用的终局 verifier，对比普通 GRPO、仅答案 masking、答案加 verifier-token masking，测量训练奖励、真实成功率和跨环境迁移差距。
